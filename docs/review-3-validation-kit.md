# Review 3 — User Validation Kit
**Purpose:** collect genuine prototype feedback for Pathway A. This is a blank protocol, not evidence that sessions occurred.

## Consent and privacy
Explain that this is a student prototype test, participation is voluntary, and feedback is used to improve the workflow. Ask permission before recording. Do not collect passwords, phone numbers, student IDs or unrelated personal data. Use tester codes T1/T2/T3. If permission to record is not granted, take anonymised notes only. Do not publish identifiable faces or voices without explicit permission.

## Facilitator opening
“Thank you for testing this prototype. I am evaluating the application, not you. Please think aloud as you use it. You can stop at any time. I will not ask for your real personal information; we will use sample details and controlled evidence.”

## Tasks
### T1 — Reporter journey
1. Open the Reporter flow using a test account.
2. Create a sample report with a provided fictional location/description.
3. Upload a designated non-personal test image.
4. Submit and locate the report status.
Observe: Can the user identify required fields? Understand submission? Find status? Know what happens next?

### T2 — AI Assist and trust
1. Enter a short, deliberately incomplete sample description.
2. Request AI Assist.
3. Ask the tester to identify what the AI suggested, what is missing/uncertain, and what they would correct.
4. Ask whether the confirmation step makes the boundary clear.
Observe: Does the user notice uncertainty? Can they correct suggestions? Do they mistake AI output for a confirmed fact?

### T3 — Authority/Staff journey
1. Demonstrate a controlled report to the Authority account.
2. Review and assign to the test Staff account.
3. Open the Staff task, update progress and add controlled after-evidence.
4. Return to Authority verification.
Observe: Are ownership, next action, evidence and final authority decision clear?

## Post-task questions
- What was easiest?
- Where did you hesitate or feel unsure?
- What did you expect to happen next?
- Was the report status understandable?
- Did the AI suggest anything unsupported or unclear?
- What single change would make this more useful or trustworthy?
- Would you use this workflow in the stated campus context? Why/why not?

## Reporting rules
- Do not turn three testers into a campus-wide statistic.
- Distinguish observed behavior from participant opinion.
- Do not fabricate quotes, completion times or success rates.
- State the actual sample size and tasks completed.
- If a task was not run, mark it “Not tested”.
- Keep original notes private; publish only anonymised evidence with permission.
